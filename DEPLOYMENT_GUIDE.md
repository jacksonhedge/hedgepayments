## ✅ Working Deployment Process

### Key Issues Resolved

#### 1. Supabase Environment Variable Errors
**Problem**: Module-level Supabase initialization causes build failures when env vars missing

**Files Fixed**:
- `/app/api/waitlist/count/route.ts`
- `/app/api/waitlist/route.ts`
- `/app/utils/supabase.ts` (main culprit)
- `/app/api/subscribe/route.ts`
- `/app/api/admin/send-email/route.ts`

**Solution**:
```typescript
// WRONG - Module level initialization
const supabase = createClient(url, key);

// CORRECT - Function-level with null checks
function getSupabaseClient() {
  const url = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const key = process.env.SUPABASE_SERVICE_KEY;

  if (!url || !key) return null;
  return createClient(url, key);
}

// Usage with null handling
const supabase = getSupabaseClient();
if (!supabase) {
  return NextResponse.json({ error: 'Database not configured' });
}
```

#### 2. TypeScript Null Check Errors
**Files Fixed**:
- `/app/admin/setup/page.tsx`
- `/app/admin/subscribers/page.tsx`

**Solution**:
```typescript
if (!supabaseAdmin) {
  setError('Supabase not configured');
  return;
}
```

### Working GitHub Actions Workflow

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build Next.js site
        run: npm run build

      - name: Setup Pages
        uses: actions/configure-pages@v4

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./out

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### Deployment Steps

1. **Make changes locally**
2. **Test build locally**: `npm run build` (should complete without errors)
3. **Commit changes**: `git add -A && git commit -m "Description"`
4. **Push to GitHub**: `git push origin main`
5. **Monitor GitHub Actions**: Check workflow at https://github.com/jacksonhedge/hedgepayments/actions
6. **Verify deployment**: Visit https://hedgepayments.com

### File Structure for Static Export

```
├── app/
│   ├── page.tsx (main landing page)
│   ├── api/ (API routes - need env var handling)
│   └── admin/ (admin pages - need null checks)
├── public/

├── out/ (generated by npm run build)
└── .github/workflows/deploy.yml
```

### Key Lessons Learned

1. **Never initialize Supabase at module level** in API routes
2. **Always check for null Supabase clients** in TypeScript
3. **Use Node.js 20+** to avoid dependency warnings
4. **Test builds locally** before pushing to GitHub
5. **Monitor GitHub Actions logs** for specific error details

### Backup Hosting Options (if GitHub Pages fails)

1. **Vercel** (fastest): `vercel --prod`
2. **Netlify**: Connect GitHub repo, set build: `npm run build`, publish: `out`
3. **Cloudflare Pages**: GitHub integration
4. **AWS S3 + CloudFront**: Static hosting
5. **VPS**: Nginx serving static files
